## Architecture decisions (locked)

- **Monorepo layout**: `apps/web` (Next.js 15 App Router + TS + Tailwind, standalone npm project), `apps/ios` (Swift/SwiftUI iOS + watchOS via XcodeGen `project.yml`), `infra/cdk` (AWS CDK v2, TypeScript, standalone npm project), `design_handoff/` (versioned copy of the design package), `docs/`.
- **No npm workspaces** — each JS project is self-contained to avoid hoisting issues.
- **Styling**: Tailwind v4 with the handoff design tokens mapped in `globals.css` `@theme`.
- **Fonts**: `next/font/google` — Instrument Serif, Hanken Grotesk, Geist Mono.
- **Data**: MongoDB (local via docker-compose; Atlas in prod). Driver: official `mongodb` package via `apps/web/src/lib/db.ts`. No Mongoose.
- **Auth (admin)**: self-hosted per-admin accounts (`admins` collection, scrypt via member-auth.ts) + roles (owner/ops/clinician) + `admin_access_log` (DPIA R4) + IP rate-limit, on an HMAC-signed identity cookie (`{adminId, role, iat}`). **MFA (TOTP) is MANDATORY** for real accounts — a no-MFA account is forced through an enrolment gate (scoped `mfa-enroll` cookie, no session) before any admin session is issued. `ADMIN_PASSWORD` (+ optional `ADMIN_EMAIL`) retained only as a bootstrap OWNER break-glass credential (password-only login → e2e unchanged), now disable-able in prod via **`ADMIN_BOOTSTRAP_DISABLED=true`** (security audit A-1). The human dashboard is served under a secret path segment **`ADMIN_PATH_SLUG`** (default `admin`; `src/proxy.ts` rewrites `/{slug}/*`→`/admin/*` and 404s direct `/admin/*` in prod) — obscurity ON TOP of the guards; the `/api/v1/admin/*` API is not obscured. Option A of ADMIN_AUTH_OPTIONS.md; managed IdP (Option B) still open. See MOCKED_APIS.md §3 + Phase 22 (security).
- **Payments**: Stripe — MOCKED (no keys). Blood testing: LetsGetChecked — MOCKED. See docs/MOCKED_APIS.md.
- **Analytics**: PostHog EU — stubbed off by default (no US-hosted scripts, per handoff).
- **Region**: eu-west-1 everywhere in CDK.
- **Hosting (user-confirmed 2026-07-02)**: Vercel (EU region, fra1/dub1) is the primary host for apps/web — fastest to market. The Dockerfile + docker-compose stack is kept working at all times so we can move to AWS (ECS/Fargate via CDK) later without a rewrite. CDK covers the AWS-side footprint only (secrets, exports bucket); no duplicate web hosting infra unless we migrate.

## Phase 21 — magic-link CODE fallback (prefetch resilience) (2026-07-03)

Email virus-scanners (Microsoft Safe Links, Mimecast, Proofpoint) prefetch URLs in emails to scan them; if a prefetch consumes the single-use magic-link token, the human gets "link expired" before they ever click. Magic-link is the PRIMARY auth method (email-only, no SIWA), so this had to be rock-solid. Two independent defences added — a confirm-button so a prefetch can't burn the link, and a typed CODE that no scanner ever submits.

- [x] **Code format** — 6 chars from the unambiguous alphabet `ABCDEFGHJKLMNPQRSTUVWXYZ23456789` (32 chars → `byte % 32` is bias-free; drops 0/O/1/I but keeps L), displayed grouped as `XXX-XXX` (e.g. `8QN-TGH`). `normalizeCode` = uppercase + strip to alphabet (case/dash/space-insensitive); `formatCode` re-groups. `member-auth.ts`: `CODE_ALPHABET`/`CODE_LENGTH`/`MAX_CODE_ATTEMPTS` + generator.
- [x] **Model** (`models.ts`): `MagicLinkTokenSchema` gains `codeHash?` (= `sha256Hex(normalizeCode(code))`, hash-only — the raw code lives only in the email) and `codeAttempts` (default 0) — both optional-compatible, no row/test churn. `MagicLinkVerifyInput` is now a refined union: EITHER `{token}` OR `{email, code}` (never neither).
- [x] **Issue** (`issueMagicLink`): now also mints a code, stores `codeHash`/`codeAttempts:0`, and returns the formatted code alongside the token. All 4 callers (magic-link/signup/reset/checkout routes) pass it through.
- [x] **Consume by code** (`consumeMagicLinkByCode(email, code, now)`): scoped to email, ignores `reset` tokens (password flow), timing-safe hash compare. Mismatch → increment `codeAttempts`; the 5th wrong try BURNS the token (`usedAt` set → the link dies too) and returns `too_many`. Match → atomic single-use burn — **the code OR the link consumes the ONE token; using one invalidates the other.**
- [x] **Verify endpoint** (`POST /auth/magic-link/verify`): accepts `{token}` OR `{email, code}`; same 200 `{member, sessionToken, needsConsent}` success and same edge states. Link-path 401s now carry `codeAvailable: true` (hint the typed-code escape hatch); 5 wrong codes → `error:"too_many"`.
- [x] **Emails** (`emails.ts`): E1 (verify) + E2 (magic link) render BOTH the button AND a prominent mono code block — "Or enter this code at arcaevo.com/signin: XXX-XXX · Useful if your email security blocks the link." New `afterButtonHtml` layout slot + `codeBlock` helper; param types gain `code`/`codeUrl`.
- [x] **Web UI — core anti-prefetch fix**: `/verify` NO LONGER auto-POSTs the token on load — it renders a big "Confirm sign-in" button (shows the email when known) that the human taps to POST (defeats prefetchers that follow links but never submit). When the link is expired/used/invalid it prominently offers "Enter the code from your email instead". `/signin` gains an "Enter a code instead" affordance. Shared `components/account/CodeForm.tsx` (auto-formats to XXX-XXX, case-insensitive, POSTs `{email, code}`) used by both; `/signin?email=` prefill from the email's code link.
- [x] **iOS** (`VerifyV3View` + `AppState` + `APIClient`): the DEBUG paste-token affordance is REPLACED by a real 6-char CODE field that works in Release — auto-formats to XXX-XXX, calls `verifyMagicLinkCode(email, code)` → same verify endpoint. - [x] **Brute-force/abuse**: code scoped to email, max 5 attempts then token invalidated, 30-min expiry, single-use, never logged. Global/IP rate-limiting on the verify endpoint remains a documented TODO (ASSUMPTIONS + MOCKED_APIS §12) — same posture as pre-Phase-21.
